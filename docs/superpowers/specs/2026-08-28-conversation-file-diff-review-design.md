# 对话文件改动追踪与 Diff 审查设计

日期：2026-08-28

## 目标

为“小码”桌面编程智能体增加 Codex 风格的文件改动审查能力。Agent 在对话中通过文件工具或本地命令新建、修改、删除文件后，对话区显示可点击的文件卡片以及 `+N / -N` 统计。点击卡片时，在聊天区右侧按需展开 Diff 审查面板，显示新旧行号和新增、删除高亮。

改动范围只包含当前对话中由 Agent 工具实际产生的变化，不使用整个仓库相对 Git HEAD 的差异，因此不会混入对话开始前已有的未提交修改。功能必须同时支持 Git 与非 Git 工作目录，并在应用重启后保留历史 Diff。

本次改造同时将整个桌面前端统一为已确认的预览风格：蓝灰项目栏、纸白工作区、桃色交互轨道，以及绿色和红色的语义化 Diff 配色。

## 已确认的产品决策

- Diff 基准是当前对话中的 Agent 操作，不是 Git HEAD。
- 右侧审查区默认关闭，点击文件后展开，可拖动宽度并关闭。
- 同一文件多次修改时，默认展示本次对话的累计变化。
- `write_file`、`replace_text` 和 `run_command` 造成的文件变化都必须追踪。
- 历史文件卡片和 Diff 快照随对话持久化，重启后仍可查看。
- 二进制或过大的文件只显示状态和大小，不渲染文本 Diff。
- 使用“工具拦截 + 工作区增量扫描”，不依赖 Git diff，也不增加 Agent 框架或托管文件工具。

## 用户体验

### 默认状态

聊天区占据项目栏右侧的完整空间。Agent 工具修改文件后，对应工具记录下方显示文件卡片。卡片包含状态图标、工作区相对路径、增加行数和删除行数。没有文件变化的工具不会生成卡片。

```text
┌────────项目/对话────────┬──────────────聊天──────────────┐
│                         │ 消息、工具状态、文件改动卡片     │
└─────────────────────────┴────────────────────────────────┘
```

### 打开审查区

用户点击文件卡片或在卡片聚焦时按 Enter，内容区变成可拖动的水平分区。项目栏和聊天保持可见，右侧显示所选文件的累计 Diff。点击其他文件卡片直接切换审查内容，点击关闭按钮恢复聊天宽度。

```text
┌────项目/对话────┬────────聊天────────┬──────Diff 审查──────┐
│                 │ 消息与输入框保持可用 │ 文件名  +84  -12  × │
│                 │                     │ 双行号、彩色修改行   │
└─────────────────┴─────────────────────┴────────────────────┘
```

右侧默认占内容区约 42%，受最小宽度约束。切换对话时恢复该对话最后查看的文件；该文件不存在或没有可预览内容时关闭审查区。不同项目和对话之间不共享选中状态或改动列表。

### Diff 表达

- 新增行：浅绿色背景、绿色文字和绿色左侧轨道。
- 删除行：浅红色背景、红色文字和红色左侧轨道。
- 上下文行：白色背景。
- 分块标题：蓝灰色背景，显示 `@@` 范围。
- 文本 Diff 显示旧、新双行号和 `+`、`-` 标记。
- 新文件、删除文件、二进制文件、截断预览、外部漂移和扫描不完整都有明确中文标签。

文件卡片用桃色左侧轨道表示“可审查入口”，Diff 内改用绿、红轨道表达实际增删。这条连续的“改动轨道”是本次界面的识别性元素。

## 视觉系统

全局界面颜色收敛为以下令牌，并替换 `gui.py` 中现有同类常量：

- `SIDEBAR = #244A67`：项目与对话导航。
- `CANVAS = #F7F5F0`：主工作区。
- `SURFACE = #FFFFFF`：消息、卡片和审查面板。
- `SIGNATURE = #F2A97E`：选中任务、卡片焦点线和主要入口。
- `DIFF_ADDED_BG = #DDF4E5`、`DIFF_ADDED_FG = #177245`。
- `DIFF_REMOVED_BG = #FCE1E1`、`DIFF_REMOVED_FG = #B33A3A`。

边框、主文字和次要文字从上述底色派生为低对比蓝灰色，保持层次清楚但不产生额外装饰。中文界面使用 `Microsoft YaHei UI`，代码、路径、统计和行号使用 `Cascadia Mono`，缺失时分别回退到 Tk 默认字体和等宽字体。

## 架构

### 改动追踪层

新增 `src/coding_agent/changes.py`，提供不依赖 Tkinter 的纯 Python 数据结构与服务：

- `FileSnapshot`：文件是否存在、类型、大小、哈希和受限文本内容。
- `ChangeSegment`：一次连续 Agent 所有权区间内的基线与最新状态。
- `FileChange`：一个相对路径在当前对话中的一个或多个追踪段、累计统计和警告。
- `ChangeSet`：一次工具调用检测到的路径集合与扫描级警告。
- `ConversationChangeTracker`：执行前快照、执行后比较、累计合并、外部漂移识别和序列化。

该模块只接受已解析的工作区路径，不直接操作 GUI，也不调用模型。路径始终保存为工作区相对 POSIX 风格字符串，以保证 Windows 与 POSIX 会话数据一致。

### 工具执行层

`ToolRegistry` 接受可选的 `ConversationChangeTracker`。`execute()` 在参数验证后、处理器执行前开始捕获，在处理器结束或抛出可恢复异常后完成捕获。

- `write_file`、`replace_text` 使用参数中的目标路径进行精确捕获。
- `run_command` 在命令执行前后扫描工作区，发现命令生成、格式化、修改或删除的文件。
- 只读工具不进行变化捕获。
- 未知工具和参数校验失败不会开始捕获。

`ToolResult` 增加仅供本地前端使用的 `changes` 字段。`ToolResult.to_message()` 继续只序列化 `ok`、`output` 和 `error`；文件快照、Diff 和 GUI 元数据不进入发给模型的 tool 消息。`CodingAgent` 的 `tool_end` 事件增加序列化后的 `changes`，不改变模型工具 schema 或 Chat Completions 调用方式。

### 会话与 GUI 层

`TaskSession` 增加当前对话的追踪器、文件变化映射和最后查看路径。创建或绑定工作目录时，用该任务自己的追踪器构建 `ToolRegistry`。因此同一目录下的不同对话分别统计自己的 Agent 改动。

新增 `src/coding_agent/diff_view.py`，封装：

- 可点击、可聚焦的文件卡片。
- 可拖动的右侧审查面板。
- 路径标题、状态、统计、警告与关闭按钮。
- 带双行号和 Tk Text 标签的 Diff 渲染。

`gui.py` 负责把现有内容区改为内部 `PanedWindow`、消费 `tool_end.changes`、向 `TaskSession` 合并数据并调用 `diff_view.py`。Diff 计算、格式化和持久化数据校验不放进 `gui.py`。

### 会话持久化

`sessions.json` 从版本 2 升级为版本 3。每个任务新增：

```json
{
  "file_changes": [
    {
      "path": "src/coding_agent/gui.py",
      "status": "modified",
      "segments": [],
      "added": 84,
      "deleted": 12,
      "binary": false,
      "truncated": false,
      "warning": null
    }
  ],
  "review_path": "src/coding_agent/gui.py"
}
```

实际 `segments` 保存受限的基线文本、最新文本、哈希和时间顺序信息，用于重启后恢复历史视图并继续追踪。版本 1 和版本 2 加载时补空的 `file_changes` 与 `review_path`，保存后升级为版本 3。加载器逐条校验变化数据，单条损坏不会导致任务或聊天历史丢失。

会话仍保存到 Git 忽略的本地 `.coding-agent/sessions.json`，并使用临时文件加原子替换。单文件、单次命令和单会话均有容量上限。

## 数据流与累计规则

1. Agent 发出工具调用，`CodingAgent` 产生 `tool_start`。
2. `ToolRegistry` 要求追踪器捕获执行前状态。
3. 工具在本地同步执行。
4. 无论返回成功、失败、超时或抛出可恢复异常，都捕获执行后状态。
5. 追踪器找出新增、修改和删除路径，并合并到当前对话。
6. `ToolResult.changes` 携带本地变化摘要；`to_message()` 排除该字段。
7. `CodingAgent` 产生带 `changes` 的 `tool_end`。
8. GUI 添加或刷新相应文件卡片，更新右侧面板并保存会话。

一个文件在某个追踪段中的第一次 Agent 变化使用执行前内容作为永久基线，之后只替换最新内容。新文件以空内容为基线，删除文件以空内容为最新状态。如果最新内容恢复到基线，该段不再贡献当前统计；没有其他有效段时文件从当前改动列表移除。

应用重启时，用持久化的最新哈希与当前磁盘状态比对。如果文件在 Agent 工具边界之外发生变化，旧段保持只读并标注外部漂移，后续 Agent 操作从当前磁盘内容建立新段。文件卡片汇总各 Agent 所有权段的统计，审查区按时间顺序分段展示，避免把外部修改归因给 Agent。

## 工作区扫描边界

命令工具无法预知会修改哪些文件，因此执行前要为候选文本文件保存受限快照，执行后再比较。扫描采用确定性的排序，并忽略：

- `.git`、`.hg`、`.svn`。
- `node_modules`、`.venv`、`venv`。
- `__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache`。
- 应用自身的 `.coding-agent` 和设计伴侣临时目录 `.superpowers`。

默认文本快照单文件上限为 1 MiB，并设置单次命令总快照上限。超过限制的文件仍可通过大小、修改时间和受限哈希识别状态，但不保存文本预览。扫描达到总上限时停止采集额外内容，继续记录可识别的路径，并在工具记录和审查面板显示“预览不完整”及受影响数量。

文本检测先检查 NUL 字节，再尝试 UTF-8 解码。二进制和无法解码的文件只保存路径、状态、旧新大小和原因。

## 错误处理与安全

- 工具失败或命令超时后仍执行后置扫描，因为失败前可能已产生修改。
- 扫描期间文件变化或消失时重新读取一次；仍不稳定则只记录状态，不生成文本 Diff。
- 无权限、解码失败或路径失效只影响对应文件，其他变化继续处理。
- 继续复用 `PathGuard` 的工作区与符号链接约束，工作区外目标不读取、不保存、不显示。
- 二进制、单文件超限或总量超限不会强行渲染；界面明确说明降级原因。
- 外部修改不会覆盖已持久化的历史段，而是触发新追踪段。
- 持久化失败时保留内存状态并提示“改动预览尚未保存”；不得声称已保存。
- Diff 组件渲染失败时显示纯文本错误卡片，不影响聊天、停止任务或切换对话。
- 文件快照只保存在本机 Git 忽略的会话数据中，不发送给模型。追踪器不读取进程环境，因此 API key 和环境变量值不会作为元数据保存。

## 测试与验收

### 改动追踪单元测试

- 新建、修改、删除、连续修改和恢复原状。
- UTF-8、空文件、无末尾换行和重复行。
- 正确计算新增与删除行数并生成双行号结构。
- 二进制、大文件、总量超限、忽略目录和不稳定文件。
- 路径穿越与指向工作区外的符号链接。
- 持久化后外部漂移产生新追踪段。

### 工具与 Agent 集成测试

- `write_file`、`replace_text` 的 `tool_end` 包含正确变化。
- `run_command` 发现新增、格式化、修改和删除的多个文件。
- 命令非零退出和超时后仍执行变化检查。
- 追踪失败只产生本地警告，不改变模型收到的原始工具结果。
- 多工具按返回顺序执行时累计结果稳定。
- 脚本化假模型完成“修改、测试失败、再次修改、测试通过”后得到最终累计 Diff。

### 持久化测试

- 版本 1、2 数据向版本 3 兼容迁移。
- 文件卡片、段、统计、警告和最后查看路径往返保存。
- 单条损坏变化数据被隔离，聊天历史仍可加载。
- 原子写入失败保留旧会话文件。
- 保存内容不包含模型配置、API key 或进程环境元数据。

### GUI 测试

- 文件卡片展示路径、状态和正负行数，并支持鼠标与键盘打开。
- 右侧面板展开、切换文件、拖动和关闭。
- 新增、删除、上下文和分块标题使用正确标签颜色。
- 切换项目或对话不会串用变化数据。
- 二进制、截断、漂移、扫描不完整和渲染失败有明确提示。
- 在 1240×800 默认尺寸和 960×640 最小尺寸下检查可读性。
- 全局主界面使用本设计定义的颜色和字体令牌。

全部自动化测试使用临时目录和脚本化假模型，不访问 DeepSeek 或其他真实 API。

人工验收时，让 Agent 在示例项目中创建文件、修改已有文件、运行格式化命令并删除文件，确认对话卡片和右侧 Diff 与实际 Agent 操作一致。重启应用后确认历史卡片仍可打开，再继续同一对话并验证新追踪段。

## 不在本次范围内

- 使用 Git HEAD、暂存区或提交历史作为 Diff 基准。
- 内置代码编辑、保存、撤销、暂存或提交功能。
- 语法高亮、语言服务器、代码导航或多标签编辑器。
- 二进制文件内容预览。
- 监控 Agent 工具执行区间之外的全部文件系统事件。
- 修改模型工具 schema，或把 Diff 快照额外发送给模型。
- 引入 `openai-agents`、LangChain 或其他 Agent 框架。
