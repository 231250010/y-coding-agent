# Codex 风格无项目对话与命名交互设计

日期：2026-08-27

## 目标

将桌面应用的任务模型调整为接近 Codex：新对话默认不属于任何项目，用户无需选择工作目录即可进行普通问答；需要文件能力时，通过输入框中的 `＋` 选择工作目录并把当前对话绑定到项目。同时为项目和对话提供一致的重命名入口，并将 Enter 改为直接发送。

本次改造必须保留现有会话历史、项目目录安全边界、命令审批机制以及“小码”的视觉风格。

## 用户体验

### 新建与无项目对话

- “开始新对话”和 `Ctrl + N` 始终创建无项目对话，不继承当前选中的项目。
- 无项目对话立即可输入和发送普通消息。
- 无项目对话不会向模型提供文件、搜索、写入或命令工具。
- 当问题需要访问本地文件时，系统提示用户通过输入框 `＋` 选择工作目录，不猜测或暗中使用默认目录。
- 无项目状态在右侧顶部显示“未选择工作目录”，输入框底部不显示伪造的目录路径。

### 选择工作目录

- 输入框左下角增加 `＋` 按钮。
- 点击 `＋` 打开轻量菜单，提供“选择工作目录…”操作。
- 选择已登记目录时，当前对话绑定到对应项目。
- 选择新目录时，以目录名创建项目，再绑定当前对话。
- 已绑定对话可以通过同一入口更换目录。
- 绑定或更换目录时保留对话消息和模型历史，只重建工具注册表与系统提示。
- 对话运行期间不能更换目录，菜单项禁用或给出明确提示。

### 侧栏与重命名

- 侧栏首先显示“对话”分组，包含所有无项目对话；其后显示“项目”分组，每个项目下列出已绑定对话。
- 项目或对话行悬停时，行右侧浮现 `···` 按钮。
- 点击 `···` 或右键该行，打开同一个上下文菜单。
- 对话菜单包含“重命名”和“删除对话”。
- 项目菜单包含“重命名”和“移除项目”。
- 右侧顶部在已绑定项目名称旁显示 `···`，其菜单包含“重命名项目”。无项目时不显示该入口。
- 重命名使用统一的小型模态窗口。Enter 保存，Esc 取消；名称会去除首尾空白，空名称不能保存。
- 项目名称仅是显示名称，不更改磁盘目录名称或路径。
- 对话名称仍可在首次发送后自动取自消息内容，除非用户已手动重命名。为此对话记录增加 `title_is_custom` 标记。

### 删除和移除

- 删除对话继续要求确认，运行中的对话不能删除。
- 移除项目只删除应用中的项目登记，不删除磁盘文件。
- 移除项目后，原项目中的对话转为无项目对话并保留历史，而不是随项目删除。

### 键盘输入

- `Enter` 发送当前消息并阻止插入换行。
- `Shift + Enter` 插入换行。
- `Ctrl + Enter` 继续发送，兼容现有操作习惯。
- 空消息或运行中的对话不会重复发送。

## 数据模型

### 内存模型

`TaskSession.project_id` 从必填字符串改为 `str | None`。任务仍拥有独立的 ID、标题、消息条目、模型历史、取消信号和运行状态，并新增 `title_is_custom: bool`。

任务必须始终存在一个 `CodingAgent`，但其工具能力由项目状态决定：

- 无项目：代理使用无工作目录模式，工具 schemas 为空。
- 已绑定：代理使用对应项目目录构建完整 `ToolRegistry`。

`ToolRegistry` 支持禁用模式，禁用模式不创建路径守卫和命令策略，并返回空工具列表。这样普通模型循环保持一套实现，不在 GUI 中复制问答逻辑。

### 持久化格式

会话文件升级为版本 2，将项目与任务分别保存：

```json
{
  "version": 2,
  "current_id": "task-id",
  "projects": [
    {"id": "project-id", "title": "项目名", "path": "C:/path"}
  ],
  "tasks": [
    {
      "id": "task-id",
      "project_id": null,
      "title": "对话名",
      "title_is_custom": false,
      "entries": [],
      "history": []
    }
  ]
}
```

加载器兼容版本 1：读取原来嵌套在项目中的任务时，将其展开到顶层并补上对应 `project_id`。保存后自然升级为版本 2。路径已经不存在的项目不再加载，但其版本 2 对话仍转为无项目对话，避免历史丢失。

## 组件职责

### 工具层

- `ToolRegistry` 负责“完整工具”或“无工具”两种明确状态。
- `CodingAgent` 不关心是否有项目，只消费工具 schemas。
- 无项目专用系统提示说明当前没有工作目录；模型需要文件时应引导用户选择目录。

### 会话层

- 创建任务时不再调用目录选择器。
- 绑定目录函数负责查找或创建项目、更新 `project_id`、重建代理并迁移历史。
- 代理重建时使用当前模式对应的系统提示替换历史第一条 system message，其余消息保持原顺序。
- 项目移除函数把关联任务的 `project_id` 设为 `None`，并将它们切换为无工具代理。

### 视图层

- Treeview 继续作为侧栏主体；悬浮 `···` 使用覆盖在当前行右侧的小按钮，只在存在有效行边界时显示。
- 上下文菜单根据目标类型生成，点击菜单操作时使用被点击的 ID，而不是依赖当前对话，避免对错误行操作。
- 顶部项目菜单只操作当前对话所绑定的项目。
- 输入框 `＋` 菜单负责目录绑定入口，不把项目选择重新放回新建对话流程。

## 状态流

### 创建并发送无项目对话

1. 用户点击“开始新对话”。
2. 应用创建 `project_id=None` 的任务和无工具代理。
3. 用户输入消息并按 Enter。
4. 模型收到空工具 schemas，正常返回文本。
5. 如果问题依赖文件，系统提示引导用户点击 `＋`。

### 将当前对话绑定到目录

1. 用户点击输入框 `＋`，选择“选择工作目录…”。
2. 系统目录选择器返回路径。
3. 应用复用已有项目或创建新项目。
4. 当前任务更新 `project_id`。
5. 应用创建完整工具代理，替换 system message 并保留其余模型历史。
6. 侧栏、顶部路径、输入框状态和持久化数据同步刷新。

## 错误处理

- 用户取消目录选择时不改变任何状态。
- 目录不可访问或在确认后失效时显示明确错误，当前对话保持原状态。
- 运行中的对话禁止绑定、更换目录或移除关联项目。
- 重命名为空时在对话框中显示错误并保持窗口打开。
- 持久化失败沿用现有状态提示，不回滚内存中的用户操作。
- 旧会话中的损坏任务条目单独跳过，不影响其他项目和对话加载。

## 视觉设计

沿用现有蓝莓侧栏、奶白工作区、杏橙操作色、微软雅黑 UI 与 Cascadia Mono，不引入新的装饰体系。悬浮 `···` 是唯一新增的明显侧栏交互，只在目标行出现；输入框 `＋` 与顶部菜单保持低调，避免破坏“克制可爱”的视觉重心。菜单和重命名窗口使用现有边框、文字和焦点颜色。

## 测试与验证

- 工具测试：无项目注册表 schemas 为空，未知工具调用安全失败；完整注册表行为不变。
- 会话测试：版本 1 数据迁移为版本 2；版本 2 无项目任务往返保存；失效项目不会带走任务历史。
- GUI 单元测试：新任务默认无项目；绑定目录保留历史；移除项目将任务转为无项目；重命名验证与持久化；菜单目标不会误用当前选择。
- 键盘测试：Enter 发送，Shift+Enter 换行，Ctrl+Enter 仍发送。
- 回归测试：现有命令审批、任务停止、会话恢复和首次消息自动命名保持有效。
- 视觉验证：在 1240×800 默认尺寸和 960×640 最小尺寸检查侧栏悬浮按钮、顶部菜单、输入框 `＋`、目录状态和发送按钮。

## 不在本次范围内

- 重命名真实磁盘目录。
- 同时为一个对话绑定多个工作目录。
- 文件附件、图片上传或远程仓库选择。
- 拖拽重排项目或对话。
- 完整复刻 Codex 的所有输入框 `＋` 菜单项。
